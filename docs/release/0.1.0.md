# ReproCut 0.1.0 release-candidate audit

`v0.1.0` must not be created from local confidence alone. The static audit
encodes repository/package/demo/release-workflow requirements:

```console
python scripts/release/audit.py --static-only
```

The final fail-closed audit additionally consumes a JSON summary bound to the
exact 40-character commit:

```console
python scripts/release/audit.py \
  --ci-evidence output/ci-evidence.json \
  --expected-commit "$(git rev-parse HEAD)"
```

The summary uses `schema_version: 1` and must mark every required native gate successful: quality, Loom,
Miri, sanitizer, supply-chain policy, real OCI, Python 3.9–3.13 wheels, Linux/
Windows/macOS CLI tests, release benchmark, crates/PyPI packages, editor,
gallery, adversarial-oracle, frozen Python-isolation, snapshot-integrity, and
all six archive targets. A missing gate is a failure, never a skip.

The checked-in demo and release smoke require evidence schema 3: lowercase
source-snapshot, oracle-spec, failure, and preparation SHA-256 identities;
normalization schema 3; an explicit oracle mode; and strict 3/3 final
verification. Resume state remains contract schema 2 and older journals require
an explicit restart rather than silent migration.

Only after that audit passes should the user:

1. create and push the exact `v0.1.0` tag;
2. approve the protected `release` environment for GitHub assets;
3. follow [registry publication order](../RELEASING.md) for crates.io;
4. publish the validated wheel/sdist through PyPI Trusted Publishing;
5. install both public packages in clean environments and rerun the real failure smoke.

The local Windows host cannot supply native Rust evidence because Application
Control blocks the installed toolchain. That limitation is recorded instead of
being bypassed or converted into a passing audit result.
