## Outcome

The final review findings are implemented in both Rust and the Python fallback:

1. Automatic mode reserves one anchor for every eligible, error-bearing stream
   before filling its four-anchor budget.
2. Route/status and URL/status tokens such as `/api/v1:404` are no longer
   treated as source locations. Recognized extensions, `<temp>`, explicit
   `at`/`-->` context, and supported extensionless build filenames remain
   volatile source locations.
3. Duration units are matched longest-first, so `10 seconds` becomes exactly
   `<duration>` in both implementations.
4. Exact cross-stream ranking ties use the explicit order stdout, then stderr.
5. `Cargo.lock` is committed. CI, release, crates.io, and PyPI graph-consuming
   commands use `--locked`, and static audit rejects lock regeneration or an
   unlocked graph command.
6. The changelog is cut as `0.1.0` dated 2026-08-12 and distinguishes evidence
   schema 3, normalization schema 3, and session contract schema 2.

## Test-first evidence

Before implementation, the focused Python suite reported four failures out of
27 cases: auto stream quota, route/status identity, URL/status identity, and
explicit extensionless source location handling. The flattened Rust
adversarial target reported four failures out of 14: route/URL identity,
extensionless location handling, complete `seconds` consumption, and explicit
channel tie-breaking. Tightening the auto test to require exactly four anchors
also exposed and corrected a five-anchor budget overflow.

The dependency release audit first failed because `Cargo.lock` and the
`dependency-lock` check did not exist, then failed on unlocked workflow graph
commands. These failures were retained as regression contracts before the
implementation was changed.

## Environment limitations — not passes

- Windows Application Control blocks the local Cargo 1.85, native Ruff, and
  later the local Python runtime with OS error 4551. Native Cargo/Clippy/Miri/
  Loom/Ruff results are not inferred; pinned GitHub CI remains their authority.
- The official Playground manifest does not expose `proptest`, so the property
  target was not executed in the flattened remote harness. The locked CI job
  names `oracle_contract`, `oracle_properties`, and `oracle_adversarial`
  explicitly, and static audit fails if that coverage disappears.
- Flattened Playground builds emit unused-item and unknown-`cfg(loom)` warnings
  because the service does not reproduce workspace boundaries or the workspace
  lint table. No Clippy claim is made from those builds.
